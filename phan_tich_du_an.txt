I. TỔNG QUAN HỆ THỐNG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FloodSOS là hệ thống quản lý lũ lụt và cứu hộ khẩn cấp cho tỉnh Nghệ An,
tích hợp 4 tầng công nghệ:

  1. Mobile App (Flutter/Dart)         → Giao diện người dùng & SOS
  2. Node.js Backend (Express)         → API Gateway, REST, Socket.IO
  3. AI Core (Python FastAPI)          → Phân tích ngập, định tuyến cứu hộ
  4. Streamlit Dashboards (Python)     → Điều phối & giám sát thời gian thực

Toàn bộ hệ thống chạy trong Docker (6 containers), giao tiếp qua mạng nội bộ
"floodsos-net".

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

╔══════════════════════════════════════════════════════════════════════════════╗
║  AI-1: MÔ HÌNH DỰ BÁO NGẬP LỤNG THEO XÃ (Commune-level Flood Forecast)   ║
╚══════════════════════════════════════════════════════════════════════════════╝

  File chính:  Gop_app/train_flood_model_final.py
               Gop_app/predict.py
               Gop_app/realtime.py

  Model đã train (Gop_app/models/):
    • model_prob_no_leak.pkl   (8.5 MB)  – Dự báo xác suất ngập tại xã
    • model_area_no_leak.pkl   (11.6 MB) – Dự báo diện tích ngập (km²)
    • model_ratio_no_leak.pkl  (12.3 MB) – Dự báo tỷ lệ diện tích ngập

  Dữ liệu huấn luyện (Gop_app/data/):
    • NgheAn_weather32full_flood_merge_by_commune_time_2023_NO_NaN.csv (340 MB)
    • NgheAn_weather32full_flood_merge_by_commune_time_2024_NO_NaN.csv (340 MB)
    • NgheAn_weather32full_flood_merge_by_commune_time_2025_NO_NaN.csv (406 MB)
    • DanSo_Xa.csv – Dân số theo từng xã

  Đầu vào (Features):
    - Dữ liệu thời tiết 32 biến (precipitation, temperature, humidity, v.v.)
    - Mã xã (commune_id), thời gian (timestamp)

  Đầu ra:
    - flood_prob:  Xác suất ngập [0,1] tại từng xã
    - flood_area:  Diện tích dự báo bị ngập (km²)
    - flood_ratio: Tỷ lệ % xã bị ngập

  Realtime pipeline:
    1. realtime.py → fetch thời tiết từ Open-Meteo API
    2. Chạy model → xuất kết quả ra realtime_outputs/
    3. scheduler_cache.py → định kỳ cập nhật cache

  Output files (realtime_outputs/):
    • flood_point_probability_rt.csv  – Xác suất ngập theo tọa độ lưới (lat/lon)
    • flood_extent_mask_rt.csv        – Mặt nạ vùng ngập
    • zone_points_rt.csv              – Kết quả theo zone
    • meta_rt.json                    – Metadata: thời gian chạy, threshold
      (Lần chạy gần nhất: 2026-03-14, threshold=0.133, cell_area=5.7m²)

  Tình trạng: ✅ Models đã train, data đã có. Cần chạy lại realtime.py
              để cập nhật flood_point_probability_rt.csv mới nhất.

╔══════════════════════════════════════════════════════════════════════════════╗
║  AI-2: MÔ HÌNH PHÂN TÍCH ĐỘ ƯU TIÊN SOS (SOS Priority Scoring)           ║
╚══════════════════════════════════════════════════════════════════════════════╝

  File chính:  Gop_app/predict_sos_priority.py
               Gop_app/train_sos_priority.py
               Gop_app/priority_api.py  (FastAPI endpoint port 8765)

  Kiến trúc mô hình: Neural Network (PyTorch)
    Input (8 features):
      lat, lon            – Tọa độ SOS
      flood_prob_near     – Xác suất ngập tại điểm gần nhất
      people_count        – Số người cần cứu
      status_enc          – Trạng thái SOS (open=0, in_progress=1, closed=2)
      hour_of_day         – Giờ trong ngày (0-23)
      is_night            – 1 nếu 22:00-05:59
      is_weekend          – 1 nếu Thứ 7/CN

    Kiến trúc Net:
      Linear(8→32) → ReLU → Dropout(0.3) → Linear(32→16) → ReLU → Linear(16→1) → Sigmoid

    Output:
      urgency_prob: float [0,1] – Xác suất SOS cần xử lý trong ≤15 phút

  Model files (Gop_app/models/):
    • sos_priority_model.pt     – PyTorch model weights (cần chạy train trước)
    • sos_priority_scaler.joblib – StandardScaler cho input normalization

  Calibration:
    • calib_model.joblib (11.3 MB) – Mô hình calibration sau khi train

  API Endpoints (:8765):
    POST /predict   → { lat, lon, flood_prob_near, people_count, status }
                    ← { urgency_prob, is_urgent, model_loaded }
    GET  /health    → { status, model_loaded }
    GET  /flood-zones → Danh sách 1000 điểm lưới ngập từ base_points_static.csv

  Fallback khi model chưa train:
    urgency_prob = min(1.0, flood_prob*0.7 + people_count/20)

  Tích hợp với Node.js Backend:
    POST /api/sos/voice → Node gọi priority-api → lưu urgency vào MongoDB + CSV

  Tình trạng: ⚠️  Model .pt chưa tồn tại trong /models/ → đang dùng fallback
              Cần chạy: python train_sos_priority.py

╔══════════════════════════════════════════════════════════════════════════════╗
║  AI-3: TÍNH TOÁN VÙNG NGẬP (Flood Zone Grid)                              ║
╚══════════════════════════════════════════════════════════════════════════════╝

  File chính:  Gop_app/priority_api.py  (GET /flood-zones)
               Gop_app/base_points_static.csv
               Gop_app/2_build_base_points.py

  Phương pháp: TWI-based heuristic (không cần model riêng)
    Công thức: p_flood = TWI/15 * 0.5  +  (1 - elev/20) * 0.3
                       + (1 - river_dist/500) * 0.2

  Dữ liệu nguồn (base_points_static.csv – 168 KB):
    1000 điểm lưới, phủ vùng Nghệ An: lat [18.77, 18.80], lon [105.58, 105.61]
    Cột: X, Y (UTM), lat, lon, TWI_UTM, DEMC_UTM (elevation), RiverDist_,
         Slope_UTM, population_density

  Output mỗi điểm:
    { lat, lon, p_flood: [0,1], priority_score: [0,100],
      priority_level: "LOW|MEDIUM|HIGH|CRITICAL", affected_population }

  Mức nguy hiểm:
    p_flood >= 0.7 → CRITICAL (radius 600m trên app)
    p_flood >= 0.4 → HIGH     (radius 450m)
    p_flood >= 0.2 → MEDIUM   (radius 350m)
    p_flood < 0.2  → LOW      (radius 280m)

  Hiển thị trên Flutter:
    map_screen.dart → CircleLayer, useRadiusInMeter=true, alpha=0.45
    Auto-zoom về centroid vùng sau khi load

  Tình trạng: ✅ Đang chạy, 1000 điểm sẵn sàng.

╔══════════════════════════════════════════════════════════════════════════════╗
║  AI-4: ĐỊNH TUYẾN CỨU HỘ FLOOD-AWARE (Flood-Aware Routing)               ║
╚══════════════════════════════════════════════════════════════════════════════╝

  File chính:  Gop_app/routing_api.py  (port 8766)
               Gop_app/route_calculator_osm.py

  Logic định tuyến:
    1. Nhận tọa độ SOS (lat, lon)
    2. Lookup flood_prob tại điểm đó từ flood_point_probability_rt.csv
    3. Nếu flood_prob < 0.5 → chế độ SELF-EVACUATION
       - Tìm shelter gần nhất (data/shelters.csv)
       - Tính đường qua OSM (osmnx + graphml cached)
       - Chia tuyến thành chặng 800m, gán flood level từng chặng
    4. Nếu flood_prob >= 0.5 → chế độ RESCUE-DISPATCH
       - Tải vị trí trạm cứu hộ (realtime_outputs/rescue_base.json)
       - Tính đường từ trạm → điểm SOS qua OSM
       - Gán phương án phương tiện từng chặng

  OSM Graph:
    realtime_outputs/osm_graph.graphml (10.2 MB) – đồ thị đường bộ cached

  Shelter data:
    data/shelters.csv           – Danh sách điểm trú ẩn chính thức
    realtime_outputs/shelters.csv – Shelter phát sinh từ realtime

  Phân loại chặng:
    flood_prob >= 0.65 → heavy    → "Bắt buộc xuồng máy / áo phao"
    flood_prob >= 0.40 → moderate → "Xe tải cao hoặc thuyền nhỏ"
    flood_prob >= 0.20 → low      → "Xe máy / xe bán tải, đi chậm"
    flood_prob <  0.20 → none     → "Xe ô tô / xe máy bình thường"

  API:
    POST /route → { lat, lon }
              ← RouteResponse { flood_level, flood_prob, mode, route[[lat,lon]],
                                segments[], total_distance_km, summary,
                                shelter?, rescue_base?, sos_target? }
    GET  /health → { status, rt_csv_exists, shelters_exists, rescue_base_exists }

  Tình trạng: ✅ Đang chạy trong Docker (floodsos-routing-api:8766)
              ⚠️  Thiếu data/shelters.csv đầy đủ → shelter lookup có thể fail
              ⚠️  realtime_outputs/rescue_base.json chưa được config

     Cần kiểm tra số lượng shelter trong data/shelters.csv có đủ cho tỉnh không

  4. REALTIME FLOOD DATA CŨ (2026-03-14)
     meta_rt.json cho thấy data cuối cùng từ 14/03/2026
     Khắc phục: Chạy lại realtime.py trong Gop_app hoặc restart container định kỳ

  5. TORCH TRONG DOCKERFILE.API
     predict_sos_priority.py import torch nhưng Dockerfile.api không cài torch
     → Nếu priority-api cần gọi model .pt, sẽ fail khi model .pt có sẵn
     Khắc phục: Sau khi train xong, cài thêm torch vào Dockerfile.api
                hoặc chuyển priority-api về dùng Dockerfile đầy đủ

  6. FIREBASE / PUSH NOTIFICATION
     firebase_messaging trong pubspec.yaml nhưng google-services.json
     có thể chưa được cấu hình đúng cho build production
